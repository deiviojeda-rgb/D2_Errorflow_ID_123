# Git

Git сохраняет изменения файлов, хранит их историю и передаёт её на сервер GitLab. После каждого готового задания делай коммит и пуш в ветку `develop`.

В командах ниже `АДРЕС_РЕПОЗИТОРИЯ`, `ИМЯ_ПАПКИ` и `ИМЯ_ФАЙЛА` — обозначения, которые нужно заменить своими значениями. Сообщения коммитов в примерах тоже замени описанием своих изменений.

## Начало работы

```bash
git clone АДРЕС_РЕПОЗИТОРИЯ
cd ИМЯ_ПАПКИ
git branch -a
```

Адрес возьми в карточке своего проекта на платформе. `clone` скачивает репозиторий вместе с его историей в новую папку. `branch -a` показывает ветки на твоём компьютере и на сервере.

Вся работа ведётся в ветке `develop`. Если она уже есть на компьютере или показана как `remotes/origin/develop`, переключись на неё:

```bash
git checkout develop
```

Если такой ветки нет нигде, создай её:

```bash
git checkout -b develop
```

Это два варианта одного действия; выполнять обе команды подряд не нужно.

## Коммит

Коммит — сохранённая точка в истории файлов. Сначала файл подготавливают к коммиту (`add`), потом сохраняют (`commit`).

```bash
git status
git diff
git add ИМЯ_ФАЙЛА
git commit -m "Описание изменения"
```

| Команда | Назначение |
| --- | --- |
| `git status` | Какие файлы изменены, какие подготовлены к коммиту, какие Git ещё не знает |
| `git diff` | Что именно изменилось в файлах, ещё не подготовленных к коммиту |
| `git add путь` | Подготовить файл к коммиту |
| `git diff --cached` | Что попадёт в следующий коммит |
| `git commit -m "сообщение"` | Сохранить подготовленные изменения в истории |

В строках `git diff` удалённое помечено `-`, добавленное — `+`. Изменённая строка показывается парой: старая версия с `-` и новая с `+`.

В `git add` можно указать несколько файлов. Добавляй только то, что нужно сдать: временные файлы в коммит не кладут. Сообщение коммита коротко объясняет, что и зачем изменилось.

Коммит сохраняет работу только на твоём компьютере. На сервер её передаёт пуш.

## Отмена изменения, которое ещё не сохранено

```bash
git restore ИМЯ_ФАЙЛА
```

Файл возвращается к состоянию последнего коммита. При успехе команда ничего не печатает. Отменённую правку вернуть нельзя: всё, что не было сохранено коммитом, теряется.

## Пуш и история

Пуш передаёт твои коммиты на сервер GitLab.

Первый пуш ветки `develop`:

```bash
git push -u origin develop
```

`origin` — имя сервера, с которого репозиторий был склонирован. `-u` связывает ветку на компьютере с веткой на сервере; дальше из этой ветки достаточно писать `git push`.

| Команда | Что показывает |
| --- | --- |
| `git log --oneline` | Историю коммитов, по одному в строке |
| `git show КОММИТ` | Изменения одного коммита; вместо `КОММИТ` подставь его номер из `log` |
| `git status` | Есть ли коммиты, которые ещё не запушены |

Коммит виден на сервере только после пуша. В GitLab по умолчанию открывается ветка `master`: чтобы увидеть свою работу, выбери в списке веток `develop`.

## Если Git сообщает об ошибке

| Сообщение | Что означает | Что сделать |
| --- | --- | --- |
| `not a git repository` | Ты не в папке репозитория | `pwd`, затем `cd` в папку, созданную `git clone` |
| `nothing to commit, working tree clean` | Изменений для коммита нет | Проверь `git status` и сохранён ли файл в редакторе |
| `Changes not staged for commit` | Файл изменён, но не подготовлен | `git add` перед `git commit` |
| `Please tell me who you are` | Git не знает, от чьего имени делать коммит | Обратись к стаффу |
| `Permission denied (publickey)` | Сервер не принял ключ доступа | Обратись к стаффу |
| `Updates were rejected` | На сервере есть коммиты, которых нет у тебя | Не делай принудительный пуш; попроси помочь разобраться |
| `src refspec develop does not match any` | Ветки `develop` на компьютере нет или в ней ещё нет коммитов | Раздел «Начало работы» и коммит перед пушем |

Краткая справка без интернета: `git status -h`, `git restore -h`, `git push -h`.
